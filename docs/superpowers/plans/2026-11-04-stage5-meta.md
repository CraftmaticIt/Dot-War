# Stage 5: Meta — Boosters, Quests, Chests, Shop, League — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Boostery celowane w węzeł w bitwie (deterministyczne, weryfikowane serwerowo), ekwipunek boosterów, zadania dzienne, skrzynki, sklep za Kryształy i liga sezonowa z nagrodami i miękkim resetem.

**Architecture:** `sim/` dostaje komendę `boost` i listę efektów (bez zmiany hashy starych wektorów). `battle/` pilnuje zestawu (loadout, max 3). Reguły meta (definicje zadań, skrzynek, cen, lig) w jednym pliku `server/game/meta_defs.json`, czytanym przez TS i Godot. Cała ekonomia meta jest po stronie serwera (`server/core/meta.ts`) z atomowymi operacjami SQL; klient tylko wyświetla profil zwracany przez `sync`.

**Tech Stack:** jak etap 4 (Godot 4.7.2 + GUT, TypeScript Node 22/Deno, Supabase).

**Spec:** `docs/superpowers/specs/2026-11-03-dot-war-design.md` (sekcja 5, „Decyzje etapu 5”)

## Global Constraints

- Boostery (ticki przy 20 Hz):
  - `rage`: grupy właściciela, których cel końcowy == węzeł, prędkość ×3/2 przez 160 ticków.
  - `shield`: te same grupy, obrażenia od wież ×2/5 przez 120 ticków.
  - `emp`: wrogie wieże w promieniu 3000 Fx od węzła nie strzelają przez 80 ticków.
  - `split`: pierwsza grupa właściciela, która dotrze do węzła w ciągu 200 ticków, ma ×2 kropek (przed walką/pułapką); efekt zużywany.
- Max 3 boostery na atak, tylko z zestawu wybranego przed atakiem; booster spoza zestawu albo ponad limit → ignorowany deterministycznie (również przy odtwarzaniu na serwerze).
- Hash: aktywne efekty dopisywane jako segmenty `e<type>,<owner>,<node>,<until>` po grupach; brak efektów = stary format (v001–v006 i b001–b005 bez zmian).
- Liga: progi `[0, 400, 800, 1200, 1600]` = Brąz, Srebro, Złoto, Platyna, Diament; nagroda sezonowa w Kryształach `[10, 25, 50, 100, 200]`; sezon = 14 dni od `2026-11-02T00:00Z`; reset: `t > 1000 → 1000 + (t − 1000) / 2`.
- Zadania: 3 dziennie (doba UTC), wybierane deterministycznie z puli wg `(uid, dzień)`; postęp tylko z wydarzeń zweryfikowanych na serwerze; nagroda w Kryształach przy ukończeniu, komplet 3 → skrzynka.
- Skrzynka: także za atak 3★ (nie w trybie ćwiczebnym); losowanie serwerowe: 1–2 boostery + 5–20 Kryształów.
- Sklep: `rage 15`, `shield 15`, `emp 20`, `split 25` Kryształów; zakup atomowy.
- Start konta: po 1 boosterze każdego typu.

## Review Focus

1. Booster w zestawie użyty 2× / 4. booster / booster spoza zestawu → ignorowany identycznie w GDScript i TS (test w Task 2).
2. Dwa równoległe zakupy przy Kryształach na jeden → jeden się udaje (test w Task 4).
3. Zadanie ukończone dwa razy przez powtórzony `finish_attack` → nagroda raz (test w Task 4).
4. Pierwsze żądanie po końcu sezonu, także równoległe → nagroda i reset raz (test w Task 4).
5. Zestaw z boosterami, których gracz nie ma → `find_opponent` odrzuca, nic nie zużyte (test w Task 4).

- `canonical()`: po grupach segmenty `e…` w kolejności dodania.
