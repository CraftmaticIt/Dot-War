# Stage 6 — PvE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Defense-puzzle campaign (15 levels) and a weekly wave arena with a server-verified ranking.

**Architecture:** Enemy dot kinds and a `spawn` command are added to the deterministic sim (GD and TS together, vectors pin them). The levels are JSON data. A PvE match is the level plus the player's placement; that placement is the whole replay, so the server re-runs it to grant stars, crystals and weekly scores.

**Tech Stack:** Godot 4.7 GDScript + GUT; TypeScript (Node 22 strip-types, node:test; Deno Edge Functions); Supabase Postgres RPCs.

**Spec:** `docs/superpowers/specs/2026-11-04-stage6-pve-design.md`

## Global Constraints

- Everything in `CLAUDE.md` "Hard rules" applies. In short:
  - ints only, `Math.trunc`/`Fx.idiv`, uint32 `>>> 0`, sorted-id iteration;
  - GD and TS change together;
  - vectors are generated by tools (the hook blocks hand edits);
  - SQL functions use `revoke ... from public, anon, authenticated` and `grant` to `service_role`.
- Old vectors v001–v007 and b001–b006 must keep their hashes. The new canonical segment `,k<kind>` appears only when kind ≠ 0.
- Kinds: `0` normal, `1` fast (`GROUP_SPEED * 3 / 2`), `2` armored (tower dmg `/ 2` after shield), `3` splash.
- Splash: `SPLASH_RANGE = 2000`, `SPLASH_DMG = 5`.
- Stars: `star_crystals = 5`. Weekly reward: `top_pct = 10`, `{"crystals": 30, "boosters": {"split": 1}}`. Week epoch: `1793577600`.
- Arena: `budget = 12`, costs `{"laser": 3, "pulse": 3, "wall": 2, "trap": 2}`, `wave_gap = 300`, `max_waves = 60`.
- Campaign safety limit: 12000 ticks.
- Player owner = 1, enemy owner = 2. All UI text is Polish.

## Review Focus

- A placement that reuses a slot, targets the core/spawn/unknown node, uses a type that is not allowed, or exceeds the limit or budget → `bad_placement`, and no match starts. Test in Task 2.
- An arena run where the core never falls must still end: at `max_waves` with no enemy groups left, score = `max_waves`. Test in Task 3.
- A splash group killed by a trap on arrival (not by a tower) must not splash. Test in Task 1.
- Two parallel `finish_pve` calls for the same level grant the crystals once. An arena result for a week other than the current one → `bad_week`. Test in Task 5.
- Finishing a level while offline keeps the local result, says "Nagroda wymaga połączenia" and does not crash. Test in Task 7.

### Task 3: PvE match, arena generator, PvE vectors

**Files:**
- Create: `pve/pve_match.gd`, `tools/gen_pve_vectors.gd`, `tests/pve_vectors/*.json` (generated)
- Modify: `server/game/pve.ts`, `.claude/skills/regen-vectors/SKILL.md` (add the generator line)

**Interfaces:**
- Consumes: Task 2 `build_world`, `player_nodes`, `validate`; Task 1 `spawn`.
- Produces:
  - `PveMatch.new(level: Dictionary, placement: Array, seed: int)` with `step()`, `over: bool`, `world` and `result() -> {stars: int, lost: int, score: int, waves_started: int, ticks: int}`. In TS: `class PveMatch` with the same members, `runPve(level, placement, seed) -> {result, hash}`.
  - `arena_level(week: int) -> Dictionary`: `arena.map` plus generated `waves`, `allowed = {}`, `level = 1`. In TS: `arenaLevel(week)`.
  - `week_index(now: int) -> int = (now - epoch) / 604800` (truncating). In TS: `weekIndex(now)`.

- [ ] **Step 1: Write the failing tests** in `test_pve_match.gd`, mirrored in the TS test where the same input is used.
  - Level 1 with a laser at 2 → `result().stars == 3`, `lost == 0`. Level 1 with no placement → `stars == 0` (core lost).
  - The match ends when all waves are spawned and no enemy groups remain, or when the core is captured, or at 12000 ticks.
  - Stars = 0 when the core is lost. Otherwise `1 + (lost <= 1 ? 1 : 0) + (lost == 0 ? 1 : 0)`.
  - Arena: `arena_level(5) == arena_level(5)`, and `arena_level(5) != arena_level(6)` in `waves`.
  - Arena with an invincible defense (a test-only level whose waves all have count 1 and a laser covering every spawn) ends with `score == max_waves`.
  - Arena where the core falls during wave index 2 (the third wave): `score == 2` (waves started before the fall, minus 1).
- [ ] **Step 2: Run and see them fail.**
- [ ] **Step 3: Implement `PveMatch`.** At tick t, queue a `spawn` for every wave with `tick == t` (owner 2, `to` = core). The arena wave generator uses `SimRng.new(week + 1)`; for wave i in `0..max_waves-1`:
  - `tick = 40 + i * wave_gap`
  - `node` = the spawn ids sorted, indexed by `rng.range_i(spawn_count)`
  - `count = 8 + 3 * i`
  - `kind = 0` if `i < 3`, else `rng.range_i(4)`

  Call the rng in this order: node, then kind. Port to TS with `rangeI`.
- [ ] **Step 4: Write `tools/gen_pve_vectors.gd`.** It writes `tests/pve_vectors/p001_level1.json` (level 1 + solution), `p002_level1_empty.json` and `p003_arena_week5.json` (a fixed placement), each `{level | week, placement, seed, expected: {result, hash}}`. `server/test/pve_vectors.test.ts` replays them with `runPve`. Run `/regen-vectors`.
